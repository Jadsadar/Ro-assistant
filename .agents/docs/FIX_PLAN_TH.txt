STEP 3 - ทำ State Machine ของ Weapon / Shield / Left Weapon / Ammo
-------------------------------------------------------------------------------

ปัญหา (Critical):
  - V2 แสดง Left Weapon ให้ทุก class ทั้งที่เว็บเก่าเปิดแค่ 6 class
  - V2 ใส่ Shield กับ Left Weapon พร้อมกันได้ ซึ่งเป็น build state ที่เป็นไปไม่ได้
  - V2 ไม่มี Ammo slot เลย สายธนู/ปืน/คุนไอ/ลูกปืนใหญ่ ประกอบ input ไม่ครบ

  กฎจริงจากเว็บเก่า (ro-calculator.component.ts:376-398):
    hiddenMap.ammu   = !isAllowAmmo()
    hiddenMap.shield = !isAllowShield()
    ถ้า ammo ถูกซ่อน และมี ammo อยู่   -> ล้าง ammo
    ถ้า shield ถูกซ่อน และมี shield อยู่ -> ล้าง shield
    showLeftWeapon = isAllowLeftWeaponByClass && !hiddenMap.shield
    ถ้ามี leftWeapon แต่ showLeftWeapon = false -> ล้าง leftWeapon
    ใน template (บรรทัด 594): leftWeapon ถูกซ่อนเมื่อ !weapon || !showLeftWeapon || !!shield

  จุดที่ต้องระวัง: เว็บเก่าผูก showLeftWeapon กับ !hiddenMap.shield
  แปลว่า "อาวุธที่ถือโล่ได้เท่านั้นจึงจะใส่มือซ้ายได้" ต้อง port ตามนี้
  ไม่ใช่ใช้แค่ class เป็นตัวตัดสิน

ไฟล์ที่ต้องสร้าง/แก้:
  สร้าง: src/lib/equipment/weapon-state.ts
  แก้:   src/components/calculator-v2/equipment-panel.tsx
  แก้:   src/components/calculator-v2/calculator-v2-shell.tsx
  แก้:   src/lib/equipment/types.ts (ถ้าต้องเพิ่ม slot definition ของ ammo)

สิ่งที่ต้องทำ:

  1) เขียน pure function
     resolveWeaponState({ classId, weaponItem }) => {
       allowsShield     : boolean
       allowsLeftWeapon : boolean
       allowsAmmo       : boolean
       ammoSubTypeId    : number | null
     }

  2) ตาราง constant ที่ต้อง port มาให้ครบ
     - ALLOW_LEFT_WEAPON_CLASSES = GuillotineCross, ShadowCross, Oboro,
                                   Shiranui, Kagerou, Shinkiro
     - ALLOW_AMMO_WEAPON_TYPES   = bow, gun, whip, instrument, shuriken
     - WEAPON_AMMO_MAP  = bow->Arrow, whip->Arrow, instrument->Arrow,
                          gun->Bullet, shuriken->Kunai
     - CLASS_AMMO_MAP   = Oboro/Shinkiro/Kagerou/Shiranui -> Kunai,
                          Mechanic/Meister/Genetic/Biolo  -> Cannonball

  3) เพิ่ม Ammo slot ใน EquipmentPanel และกรองชนิดกระสุนตาม ammoSubTypeId
  4) ทำ mutual exclusion: มี shield -> ซ่อน leftWeapon, มี leftWeapon -> ซ่อน shield
  5) เปลี่ยนอาวุธหลักแล้ว ต้องล้าง shield/leftWeapon/ammo ที่ไม่เข้ากันอัตโนมัติ

Acceptance criteria:
  - ใส่ Shield และ Left Weapon พร้อมกันไม่ได้ในทุกทาง (ทั้ง UI และ state)
  - เปลี่ยนเป็นอาวุธสองมือ -> Shield ถูกล้างทันที
  - class ที่ไม่อยู่ในลิสต์ 6 class -> ไม่เห็นช่อง Left Weapon เลย
  - Ammo แสดงเฉพาะเมื่อ weapon type หรือ class ต้องใช้
  - เปลี่ยนอาวุธจากธนูเป็นปืน -> ลูกธนูที่ค้างถูกล้าง
  - test ammo จาก STEP 0.2 เปลี่ยนเป็น PASS

STEP 4 - แก้ semantics ของ refine
-------------------------------------------------------------------------------

ปัญหา (High):
  scripts/build-catalog.ts:345-349 และ 361-365 เขียนว่า
    isRefinable: item.isRefinable ?? equipSlots.some(slot => rule.allowsRefine)
  คือถ้า source ไม่มีค่า จะ fallback เป็น true ตาม slot
  แต่เว็บเก่าอ่านว่า  isRefinable ?? false  (equipment.component.ts:171)

  ผล: source เก่ามี isRefinable === true เพียง 3 records
       แต่ catalog ใหม่ mark accessory ที่ equip ได้ 383 ชิ้นเป็น refinable ทั้งหมด
       และ V2 ยังใช้ rule.allowsRefine ระดับ slot ซ้ำอีกชั้น

  ผลข้างเคียงที่ต้องตรวจด้วย:
    resolveCanGrade() ที่ catalog-rules.ts:139-160 รับ isRefinable เข้าไป
    ตัดสิน grade ด้วย (บรรทัด 147: if (item.isRefinable === false) return false)
    การแก้ fallback จะกระทบรายการ gradable ต้องตรวจว่าไม่เปลี่ยนโดยไม่ตั้งใจ

ไฟล์ที่ต้องแก้:
  scripts/build-catalog.ts
  src/lib/equipment/catalog-rules.ts
  src/components/calculator-v2/equipment-panel.tsx

สิ่งที่ต้องทำ:
  1) เก็บค่า 3 สถานะแยกกัน: true / false / unknown (missing)
     ห้ามยุบ unknown เป็น true
  2) port กฎ legacy ต่อ item type สำหรับกรณี unknown
  3) V2 ตัดสิน refine จาก "ไอเทมจริง" ไม่ใช่จาก slot rule
  4) accessory ที่ไม่ refinable ต้องไม่มี refine control และ reset เป็น 0
  5) เปลี่ยนไอเทมแล้ว refine ที่ invalid ต้อง reset
  6) rebuild catalog แล้วเทียบจำนวน refinable/gradable ก่อน-หลัง

Acceptance criteria:
  - รายการ refinable ตรง fixture refinable.json
  - accessory ส่วนใหญ่ไม่มีปุ่ม refine
  - รายการ gradable ไม่เปลี่ยนแบบไม่ได้ตั้งใจ (มี test เทียบก่อน-หลัง)
